# Data interface (no proprietary study data included)

The study data are proprietary and are not distributed with this repository. The code runs
on user-supplied inputs following the schemas below or on synthetic demonstration inputs
generated by `scripts/generate_synthetic_data.py`.

Synthetic values are not derived from the study data and are not intended to reproduce any
numerical result in the manuscript.

## 1. `continuous_logs.csv`

Continuous LWD measurements on the 0.125 m grid. Group D is calculated on this continuous
sequence before matching to core depths.

| Column | Type | Unit | Meaning |
|---|---|---|---|
| `log_id` | string | - | unique log-grid row identifier |
| `well_id` | string | - | well identifier |
| `depth_m` | float | m | measured depth on the continuous grid |
| `GR` | float | API | gamma ray |
| `CNL` | float | % | compensated neutron |
| `DEN` | float | g/cm^3 | bulk density |
| `AC` | float | us/ft | acoustic transit time |
| `RLA5` | float | ohm*m | deep lateral resistivity |

Rows must be orderable by `(well_id, depth_m)`. The manuscript workflow uses a 0.125 m
spacing and requires the neighboring grid values used by the centered or strictly causal
Group D windows.

## 2. `core_samples.csv`

Core-matched rows used for FZI labels and the two Group C regressors.

| Column | Type | Unit | Meaning |
|---|---|---|---|
| `sample_id` | string | - | stable sample identifier |
| `well_id` | string | - | well identifier |
| `depth_m` | float | m | core-matched depth |
| `porosity_pct` | float | percentage points | recorded core porosity |
| `permeability_mD` | float | mD | recorded core permeability |

Recorded porosity values are used as provided; the code does not attempt to reverse or
impute the source-report 4.00% reporting convention.

## 3. `lithology_corpus.csv`

Lithology-labelled rows used to refit the 18-class eRF pipeline that produces Group B.

| Column | Type | Unit | Meaning |
|---|---|---|---|
| `lith_record_id` | string | - | unique lithology-corpus row identifier |
| `well_id` | string | - | well identifier |
| `depth_m` | float | m | measurement depth |
| `GR`, `CNL`, `DEN`, `AC`, `RLA5` | float | as above | original five curves |
| `source_sample_id` | string/blank | - | matching `core_samples.sample_id` when applicable |
| `lithology_class_id` | integer | - | 0--17 in the order in `configs/erf.yaml` |

`source_sample_id` allows the fitting code to exclude records corresponding to an active
CP-calibration set without publishing any measurement-bearing split file.

## Public-data boundary

The repository contains no real well-log curves, core measurements, thin-section images,
intermediate study feature matrices, fitted study checkpoints, or per-sample study predictions.
The release does not include study-specific row identifiers for the fixed 178-sample calibration subset.
Rather than reconstructing or inventing those historical identities, the repository publishes the exact
Table 3(b) well/class quotas in `metadata/fold_assignments.csv` and implements the stated stratified
selection protocol. An authoritative anonymized row-ID file can be supplied separately when available.

## Synthetic demonstration inputs

Generate the synthetic three-file input set with:

```bash
python scripts/generate_synthetic_data.py
```

This creates:

```text
data/synthetic/
  continuous_logs.csv
  core_samples.csv
  lithology_corpus.csv
  manifest.json
```

The files are git-ignored and can be regenerated at any time.

## Optional study-specific split metadata

If an authoritative split file is available, pass it with:

```bash
python scripts/train_grqnet.py --split-metadata <path>
```

Its `sample_id` values must match `core_samples.csv::sample_id`, and `is_main_calibration` must flag
exactly the authoritative 178 rows. The loader validates the published 178-row total and well-by-class
calibration counts before training. No row-level split file is fabricated by this repository.
